# 技术文档导航

参赛项目名称为 **CatalystFlow**。

本目录解释“为什么这样设计”；运行命令集中在 `../code/README.md` 和
`../runtime/README.md`，数值证据集中在 `../results/`。

## 推荐阅读顺序

1. `method_description.docx`：手动定稿的技术路线内容基准；同名 PDF 为评审版，
   Markdown 为可检索文本镜像。内容涵盖算法流程、特征、模型、化学机理、DFT、
   智能体、防泄漏、创新点和局限性。
2. `reproduction_guide.md`：数值复现环境与智能体环境的调用方法。
3. `final_delivery_guide.md`：提交目录、复现方法、验证范围与交付检查表。
4. `resume.pdf`：团队履历。

技术路线图的独立高分辨率版本位于
`../results/figures/framework_overview.png`，便于评委单独放大查看。

数值结果、智能体分析、外部证据和最终推荐已合并为一套报告。手动定稿的
`../results/results_and_analysis.docx` 是内容基准，同名 PDF 为评审版，Markdown 和
JSON 分别提供可检索文本与机器可读数据。

## 四个容易混淆的概念

- **统一框架不等于同一个代理模型**：代理模型是近似“反应条件→产率”的预测模型；
  “代理”强调其在顺序优化中替代昂贵实验输出预测均值与不确定性。两类反应共享
  顺序优化闭环和期望改进接口，但依据反应机理与变量结构使用不同的最终模型。
- **离线预言器（OfflineOracle）不等于训练集**：它模拟实验反馈接口，只在推荐索引确定后释放
  一条反馈；尚未查询的 Yield 对优化器不可见。
- **DFT 解释不等于 DFT 排序**：DFT 指导研发和解释已选候选，最终模型
  不因解释结果重新排序。
- **最终推荐反应条件不等于优化器第一名**：`optimizer_rank` 是已查询条件的不可变数值
  排序；`selected_optimizer_rank` 是 DeepSeek 基于六维现实可行性评估，从已查询 Top-5
  反应条件中作出的执行建议。

正式指标字段中保留 t95 和 AUC，正文在首次出现时给出完整含义；高斯过程、
随机森林、期望改进和密度泛函理论均优先使用中文全称。
